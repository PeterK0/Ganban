# Projects, tasks & events

The spine of Ganban is three nested ideas: a **project** holds **tasks**, and
tasks play out over time as **events**. Get this flow and the rest follows.

## Projects — the container

A project is a body of work: a course, a client, a build, a research thread.
Inside it live its tasks, its calendar, its files, its discussion, and its
assistant. Big projects break into **areas** (sections) so the task list stays
legible.

- **Pin** the projects you live in — they sit at the top of the left rail.
- Each project can have its own **assistant personality** and its own
  **knowledge** (its files + notes, searchable by the assistant).
- The **Home** view stitches every project together: today's events, what to
  pick up, open tasks, tracked time — your whole world in one glance.

## Tasks — the unit of work

A task is one thing to do. It carries:

- **Status** — To Do → In Progress → Blocked → Done.
- **Priority** — Low / Medium / High.
- **Deadline**, a **description** (rich text, links), **comments** (discuss it
  with teammates or the assistant), **files**, and **time tracking**.
- **Linked events** — the meetings/lectures/deadlines that belong to this task.

Open a task in the right-hand pane to edit it in place; linked items (events,
files) open there too, with ‹ › to step back.

## Events — work on a timeline

Events are your calendar — **Month / Week / Day / Agenda**. An event can be
**linked to a project** (so it shows in that project's world) and **to a task**
(so a lecture sits with the task it prepares). You can:

- Import external calendars (ICS / webcal) — a timetable lands as events.
- Click a day in Month view to see that day's events in the side pane and add one.
- Filter the Agenda (hide unconnected / orphaned / past, or by project/task).
- Get reminders before an event starts.

## How it flows

> A **project** defines the work → its **tasks** are the steps → the steps happen
> on dates as **events** → events link back to the task and project they serve.

When a new timetable arrives, its events come in unlinked; you (or, soon, the
secretary — see *Working with the assistant*) route each to the project whose
code it matches. The assistant, grounded in a project's tasks/files and given the
right tools, then helps you actually *do* the work — not just track it.
